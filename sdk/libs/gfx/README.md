# gfx

Status: implemented and growing; current as of 2026-11-11. Used by Blocks, Turbo Blast, Fruit Merge, Pumpkin Smash, Crew Tasks, Claw, Neon Drive, After Dark, Cradle, Marble Maze, Arcade, SkiFree, and the 1-bit games through MacCanvas (Dino, Invaders, Missile Command, Stratego, StuntCopter). The plan for the rest is `docs/plans/game_api_consolidation.md`, Phase 2.

Drawing into any RGB565 buffer, usually the frame a VideoBlit app draws each frame. Header-only (the component has no sources and no `REQUIRES`), with no LVGL, ESP-IDF or `System` calls, so built-in apps, ELF apps and the sim's tests share it.

- **Built-in apps:** add `gfx` to `REQUIRES` and include `gfx/surface.hpp`.
- **ELF apps:** `set(VIPER_LIBS gfx)` before `project_elf()` (`apps/README.md`, "Game libraries").
- **Tests:** `sim/tests/test_game_libs.cpp`.

| Header | What |
| --- | --- |
| `gfx/color.hpp` | `Pixel` (RGB565), `Rgb`, `rgb(r, g, b)`, `rgb_hex(0xRRGGBB)`, `unpack`, `scale`, `mix`, `blend(dst, src, a32)` (alpha 0 to 32), `add` (saturating) |
| `gfx/rect.hpp` | `Rect`: `right`, `bottom`, `contains`, `grow`, `intersect`, `overlaps` |
| `gfx/font.hpp` | `Font` (fixed width, or proportional with `advance_of`), `advance()`, `text_pixels()` (a string's ink, for canvases that aren't RGB565), and `kFont5x7`: capitals, digits and punctuation, packed into bits at compile time |
| `gfx/font3x5.hpp` | `kFont3x5`: digits, capitals and punctuation in 3x5, for scores and HUDs |
| `gfx/font_unscii8.hpp` | `kFontUnscii8`: LVGL's unscii-8, all of printable ASCII in 8x8 cells. LVGL's unscii-16 is the same font, so draw this at scale 2 (one pixel higher to match). Generated by `tools/gen_unscii.py` |
| `gfx/surface.hpp` | `Surface`: a buffer, its size, its stride and a clip rectangle. `set`, `add`, `blend`, `clear`, `fill`, `fill_blend`, `darken`, `frame`, `hline`, `vline`, `text`, `text_centered`; `centered()` for a fixed layout centered on a bigger panel, `translated()` to move (0, 0) (a screen shake); and `text_width()` |
| `gfx/shapes.hpp` | `disc`, `ring` and `line` (any angle and width), with smoothed edges; `ellipse`, `poly` (`Vec2` or `float[2]` points), `poly_outline`, `round_rect` and `span`, with hard edges. Float coordinates, a pixel's center at +0.5, and an alpha on each. `pixel_line` is a Bresenham line on whole pixels, for a pixel-art look |
| `gfx/image.hpp` | `Image`: pixels the app owns (usually const tables), RGB565, RGB565 with an alpha byte, A8 coverage, or 8-bit indices into a palette (index 0 clear); `sub()` for an atlas cell, `with_palette()` for a palette swap. `blit` (flipped, integer scale), `blit_tinted` (the shape in one color: shadows, silhouettes, A8 masks), and `blit_transformed` / `blit_transformed_tinted` (scaled and turned about an anchor, crisp or smooth) |
| `gfx/ui.hpp` | Menus for framebuffer games: `Menu` (action, toggle, choice and number rows; `update()` from `ui::Keys`, `draw()` centered or as labels and values), `dialog()` (a bordered box, a heading, an optional menu), `hint_bar()` (the system hint bar's look: button chips and labels, B at the right end), and `Theme` (colors named as in `ui_theme.hpp`, font, scales, an outline or glow around text). The app plays its own sounds for each `Result` |
| `gfx/lobby.hpp` | `ui::LobbyView`: the link play lobby for framebuffer games, the same pages as the LVGL lobby (`ui::LobbyScreen`). It draws a `LobbySnapshot` (plain data: fixed-size text, no pointers) and turns `ui::Keys` into a `LobbyCommand`; it knows nothing of the link. Built-in games fill the snapshot from `viper::link::Lobby` with `ui::lobby_snapshot()` (`components/ui/include/lobby_snapshot.hpp`); ELF games will get the same layout from the C API (Phase 3 of `docs/design/multiplayer.md`). `notice()` shows a line in a box for a few seconds |
| `gfx/present.hpp` | `fit_integer()`: the whole-number scale a layout fits the panel at, and where it's centered. `MonoPresenter`: a black and white canvas (a byte per pixel) to the panel, 1:1, scaled up, or averaged to gray, as MacCanvas presents |

```cpp
// In an ELF app's loop()
gfx::Surface s(viper_frame_begin(), viper_display_width(), viper_display_height());
s.fill({0, 0, s.w, 20}, gfx::rgb(16, 12, 32));
s.text(gfx::kFont5x7, "SCORE 1200", 4, 6, gfx::rgb(255, 255, 255));
viper_frame_mark_dirty(0, 0, s.w, 20);
viper_frame_end(0);
```

The surface doesn't own or present the pixels: the app gets the frame and sends it, as before. `set_clip()` keeps drawing inside an area; `reset_clip()` undoes it.

Games laid out for 320x240 draw on `Surface(fb, w, h).centered(320, 240)`: (0, 0) is the layout's top left, and drawing can still reach the margins around it (`clear()` fills them too).

`gfx/benchmark.hpp` holds the cases the GFX Bench app (`apps/gfx_bench`) times, in the app and in the firmware; it isn't part of the drawing API.

Changed areas don't need tracking here: `viper_frame_mark_dirty()` and `Bsp::mark_region_dirty()` feed the BSP's dirty-span tracker, which merges them.

Next, from the plan: an asset tool that turns PNGs into `Image` tables, and effects (shake, flash and fade) when a second game wants them.
