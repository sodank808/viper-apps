# Viper app SDK

Status: generated by viper's scripts/export_sdk.py; don't edit. See VERSION.

What an ELF app for Viper builds against: the app API (`include/viper_app.h`,
`viper_link.h`), the firmware's LVGL headers (`lvgl/`), the shared game
libraries (`libs/`, asked for with `set(VIPER_LIBS ...)`), and the checker that
runs after every link (`tools/check_app_elf.py`) with the list of every function
the firmware exports to apps (`exports/`).

An app project's `CMakeLists.txt`:

```cmake
cmake_minimum_required(VERSION 3.20)
set(COMPONENTS "main" CACHE STRING "List of components to include")
include($ENV{IDF_PATH}/tools/cmake/project.cmake)
project(my_app C CXX)
set(VIPER_LIBS gfx game)   # optional
include(../sdk/viper_sdk.cmake)
project_elf(my_app)
```

Build it with `idf.py elf` under the ESP-IDF version in `VERSION`.

`wfc` and `drum_synth` have sources as well as headers; an app that uses one
lists `libs/<lib>/src/*.cpp` in its own `main/CMakeLists.txt`.

Versions: the major version is the app ABI (`VIPER_APP_ABI_VERSION` in
`viper_app.h`); firmware runs apps whose ABI is in its supported range. Exports
are only ever added (`exports.lock` lists every one), and firmware refuses an
app that calls one it doesn't have, with a message naming it.
